# Design

## World

"Elevated FMCSA/DOT paperwork" — the app reads as a precise compliance instrument, not a generic SaaS dashboard. The palette and structural language are lifted directly from the real FMCSA "Driver's Daily Log" form (studied first-hand from the official source document), not invented: paper-white ground, near-black ink text, one committed deep navy carrying section bands and primary actions. Raised by two dealt design-catalog challengers weighed during direction selection: an oscilloscope's graticule precision (fine hairline-tick measurement discipline, not its dark phosphor palette) and a Wim Crouwel type-specimen's visible structural grid (the ruled grid as a celebrated armature across the whole surface, not just the log sheet).

Chosen via Impeccable's `concept-seed` mechanism (mode: operate, seed key `b1e93110`, assigned index 3 of 7 grounded directions authored from the dispatcher/trucking/logistics world) rather than picked freely, specifically to avoid the generic blue-gradient-card look most AI-generated ops tools default to.

## Tokens

- **Color** — Tailwind's built-in `slate` scale for all neutrals (page background `slate-50`, card surfaces `white`, hairline borders `slate-300`, secondary text `slate-500`/`slate-600`, body text `slate-900`). One custom accent family added via Tailwind v4's `@theme` in `src/index.css`: `navy-50/200/500/600/700/900` (`--color-navy-600: #1b2a47`), used for the header band, primary buttons, active tab state, focus rings, and the log sheet's status line. Duty-status/stop-type colors are a separate, strictly functional palette (never decorative): green/red/amber/violet/blue/rose for pickup/dropoff/fuel/break/rest/restart.
- **Type** — system-ui stack throughout (no custom font import); this is Operate mode, so a workhorse system stack is the deliberate choice, not an oversight. All numeric data (miles, hours, cycle input, log sheet totals) uses `tabular-nums`. Field/section labels use a small uppercase, letter-spaced treatment (`text-[11px] font-semibold uppercase tracking-wide text-slate-500`) echoing real form field labels ("TOTAL MILES DRIVING TODAY"-style).
- **Spacing/shape** — `rounded-sm`/`rounded-md` throughout (precise, not soft/consumer-rounded); 1px hairline borders (`slate-300`) on every card and control.
- **Grid armature** — the recurring structural motif. Manifests as: (1) `RuledDivider`, a thin ruled line with tick marks (the log sheet's own hour-axis motif) used under the navy header and between major sections; (2) `.ruled-grid-watermark` in `index.css`, a faint repeating-linear-gradient graph-paper pattern on the pre-submission empty state, so the grid is present from the first viewport rather than only once there's data.
- **Motion** — one motion thesis shared by two surfaces, plus fast supporting feedback everywhere else. The focal idea: *lines draw themselves rather than appearing instantly* — the ELD log sheet's duty-status path traces in via `stroke-dasharray`/`stroke-dashoffset` (800ms, re-fires on every day switch, `ELDLogSheet.tsx`), and the route map's polyline does the same (1100ms, `RouteMap.tsx`'s `AnimatedPolyline`), so a route and a timeline read as one coherent visual idea — both are lines that resolve — instead of two unrelated effects. Map stop markers pop in with a per-stop stagger (capped at 600ms total) after the line. Tab switches (Route Map ↔ Daily Logs, day-to-day within a trip) cross-fade via the native View Transitions API (`utils/viewTransition.ts`, 200ms) with a plain-update fallback where unsupported. The summary strip's figures count up on arrival (`useCountUp`, ease-out cubic, 600ms) rather than appearing instantly. Results settle in with a short staggered fade+rise (`.animate-reveal`, 420ms, summary strip then tabs +70ms). Buttons and tabs get fast (150ms) hover/press feedback (`active:scale-[0.97]`-style). Every animation has a `prefers-reduced-motion` path — the draw-ins skip straight to their final state, everything else's transform is dropped via the CSS media guard in `index.css`.
- **Browser surfaces** — `::selection` themed to navy/white; the log sheet's horizontal-scroll container (`.eld-scroll`) gets a themed thin navy-tinted scrollbar rather than the browser default.

## Components

- `SummaryStrip` — deliberately **not** the hero-metric-tile pattern (big number/small label ×3, which is an explicitly banned scaffold). Reads as a document header line instead: labeled data pairs on one ruled strip, matching how the real FMCSA form's own header presents "TOTAL MILES DRIVING TODAY" etc.
- `ELDLogSheet` — the centerpiece; an inline SVG recreation of the real RODS grid (4 duty-status rows, 24-hour axis with hour/quarter-hour ticks in the authentic Mid/1-11/Noon/1-11/Mid convention, one continuous stepped status path, a remarks strip, a totals column). `groupCloseRemarks` in `logSheetGeometry.ts` merges remark labels that land within 35px of each other (same real-world moment/location, e.g. a fuel stop immediately followed by resuming driving) rather than letting them render as overlapping garbled text — found and fixed via direct visual testing against real engine output, not assumed correct.
- `RouteMap` — react-leaflet + OSM tiles, navy route line, a typed marker/legend system (current/pickup/dropoff/fuel/break/rest/restart) so the color coding is explained, not just discoverable by clicking.
- `TabButton` — one shared component for both the Route-Map/Daily-Logs switch and the per-day log tabs, styled consistently (navy when active, ruled-border white otherwise).

## Verification

Manually verified live in the Browser pane against real engine-generated multi-day trip data (not placeholder content) at desktop (1440px, default width) and mobile (375px) viewports: empty state, form validation states, the map with real tiles/markers/legend, and both log-sheet days including the close-remark-merge fix. No formal screenshot-diff finish review was run (no comp exists — this is a code-led build per project constraints — and this session's Browser pane tool has no save-to-disk primitive for the `.impeccable/review/` screenshot files that review expects); verification instead relied on direct interactive inspection, which is where the remarks-overlap bug above was actually caught. Disclosed here rather than silently skipped.
